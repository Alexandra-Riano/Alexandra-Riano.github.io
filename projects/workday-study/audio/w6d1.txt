Week 6, day 1. Condition rules. [[slnc 1200]] Today's objective is Condition Rules, in the Business Processes domain. [[slnc 600]] In one line: Distinguish entry, validation, while-running, and exit conditions. [[slnc 1200]] Let's start with the mental model. [[slnc 500]] Entry decides whether a step runs; it works on every step type except Initiation. Validation checks data on Initiation and Action (review) steps and stops the process if a condition applies. A validation is either Warning (the user can continue) or Critical (the user must fix the data), and you can write a custom validation message. While Running works only on approval chains and decides whether the next approver in the chain acts. Exit works on approval chains and Integration steps and decides whether the step can complete; a common exit rule stops a chain after two approvals. Before the completion step, Hire data such as job profile and location is still proposed, so rules that run earlier use "proposed" fields. Create Condition Rule only saves a rule; Maintain Step Conditions attaches it to a step. [[slnc 1200]] Now, the distinctions you need to know. [[slnc 500]] Entry: Should the step start?. [[slnc 700]] Validation: May the process continue? (Warning or Critical). [[slnc 700]] While Running: Does the next chain member act?. [[slnc 700]] Exit: May the running step complete?. [[slnc 700]]  [[slnc 600]] Here's how it shows up at work. [[slnc 500]] Run executive approval only above a compensation threshold by attaching an entry condition. [[slnc 1200]] Task and report names to recognize: Create Condition Rule, Maintain Step Conditions, Configure Validation Message, Test Rule, and Configure Optional Fields. [[slnc 1200]] And the exam trap to watch for. [[slnc 500]] The four types are not interchangeable and are not available on every step type. [[slnc 1500]] Quick check.
