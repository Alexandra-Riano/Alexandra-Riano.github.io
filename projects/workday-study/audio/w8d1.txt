Week 8, day 1. Security policies. [[slnc 1200]] Today's objective is Domain versus business process Security Policies, in the Security domain. [[slnc 600]] In one line: Separate secured-item access from business-process participation, then activate changes. [[slnc 1200]] Let's start with the mental model. [[slnc 500]] Domain policies grant View or Modify access to items and may inherit parent permissions. business process policies control initiation, action, approval, delegation, cancel, rescind, deny, and similar event actions. Saved changes remain pending until activated. [[slnc 1200]] Now, the distinctions you need to know. [[slnc 500]] Can see/modify item?: Domain policy. [[slnc 700]] Can initiate/approve event?: business process policy. [[slnc 700]]  [[slnc 600]] Here's how it shows up at work. [[slnc 500]] If HR can view worker data but cannot initiate Change Job, inspect Change Job business process security rather than adding broad domain access. [[slnc 1200]] Task and report names to recognize: Edit Domain Security Policy, Edit Business Process Security Policy, Activate Pending Security Policy Changes, and View Security for Securable Item. [[slnc 1200]] And the exam trap to watch for. [[slnc 500]] Saving a policy edit does not activate it. Review, activate, and test with suitable accounts. [[slnc 1500]] Quick check.
