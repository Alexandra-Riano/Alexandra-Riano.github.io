Today's objective is Routing, Delays  and  Effective Dates, in the Business Processes domain. [[slnc 600]] In one line: Control who acts on a step, when it runs, and which definition version applies. [[slnc 1200]] Let's start with the mental model. [[slnc 500]] Maintain Advanced Routing adds routing restrictions: Exclude Initiator, Exclude Prior Approvers, and Exclude Event Subject. If everyone assigned is excluded, the step is skipped unless you name an alternate security group, relative to the transaction or to the excluded user. Use routing restrictions when exclusion depends on how a user is involved in this event; use condition rules to exclude groups regardless of the event. Maintain Step Delay pauses the process before a step, based on the prior step's completion, the initiation date, or a field such as Effective Date; Recalculate Delay on Correct keeps it accurate. Rule-based calendars are set per business process type. An event uses the definition that is in effect when it is initiated, never a future-dated version, and subprocesses use the version in effect when the parent started. Steps with the same order letter run in parallel. [[slnc 1200]] Now, the distinctions you need to know. [[slnc 500]] Routing restriction: Excludes someone by their role in this event. [[slnc 700]] Condition rule: Excludes regardless of the event. [[slnc 700]] Step delay: Pauses before a step runs. [[slnc 700]] Definition version: The one in effect at initiation. Add Exclude Initiator on the review step and route it to the HR Partner's manager as the alternate, relative to the excluded user.
