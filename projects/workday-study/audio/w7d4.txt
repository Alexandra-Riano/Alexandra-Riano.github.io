[[slnc 1200]] Recap: Condition Rules. [[slnc 500]] Entry decides whether a step runs; it works on every step type except Initiation. Validation checks data on Initiation and Action (review) steps and stops the process if a condition applies. A validation is either Warning (the user can continue) or Critical (the user must fix the data), and you can write a custom validation message. While Running works only on approval chains and decides whether the next approver in the chain acts. Exit works on approval chains and Integration steps and decides whether the step can complete; a common exit rule stops a chain after two approvals. Before the completion step, Hire data such as job profile and location is still proposed, so rules that run earlier use "proposed" fields. Create Condition Rule only saves a rule; Maintain Step Conditions attaches it to a step. [[slnc 700]] Entry: Should the step start?. [[slnc 500]] Validation: May the process continue? (Warning or Critical). [[slnc 500]] While Running: Does the next chain member act?. [[slnc 500]] Exit: May the running step complete?. [[slnc 500]] Remember the trap: The four types are not interchangeable and are not available on every step type. [[slnc 1300]] Recap: Business Process Notifications. [[slnc 500]] Workday sends system notifications, for example when a task arrives in My Tasks. Custom notifications are added to a definition with Add Notification. They trigger on the process status (such as Completed) or when a step is entered or exited, and conditions can be added; the trigger and the condition must both be met. Recipients can be participants, other users, or security groups. Message content mixes text and fields; a field the recipient cannot access shows as [not available]. Receiving a notification never grants access to the process. Custom notifications do not turn off system notifications. Delivery depends on configuration and preferences: immediate email, a daily digest email, and push notifications. Edit Tenant Setup - Notifications holds tenant-wide email and delivery settings. Select Do Not Include Notification Details Link for recipients who have no Workday account. [[slnc 700]] Notification: Inform someone. [[slnc 500]] business process step: Require or automate work. [[slnc 500]] Trigger: Status, or step entry or exit. [[slnc 500]] System versus custom: Custom ones do not turn system ones off. [[slnc 500]] Remember the trap: A notification is not an Approval or Action and does not confer access. [[slnc 1300]] Recap: Routing, Delays  and  Effective Dates. [[slnc 500]] Maintain Advanced Routing adds routing restrictions: Exclude Initiator, Exclude Prior Approvers, and Exclude Event Subject. If everyone assigned is excluded, the step is skipped unless you name an alternate security group, relative to the transaction or to the excluded user. Use routing restrictions when exclusion depends on how a user is involved in this event; use condition rules to exclude groups regardless of the event. Maintain Step Delay pauses the process before a step, based on the prior step's completion, the initiation date, or a field such as Effective Date; Recalculate Delay on Correct keeps it accurate. Rule-based calendars are set per business process type. An event uses the definition that is in effect when it is initiated, never a future-dated version, and subprocesses use the version in effect when the parent started. Steps with the same order letter run in parallel. [[slnc 700]] Routing restriction: Excludes someone by their role in this event. [[slnc 500]] Condition rule: Excludes regardless of the event. [[slnc 500]] Step delay: Pauses before a step runs. [[slnc 500]] Definition version: The one in effect at initiation. [[slnc 500]] Remember the trap: An event initiated June 14 uses the version effective then, even if its effective date is June 29 and a newer version starts June 16.
